# 13 增量开发计划与本轮答案

技术栈按用户要求：Go + net/http、MySQL、Vue 3 + TypeScript + Vite、Docker Compose、Go testing、Playwright。本轮只交付调查、规格和计划，没有业务代码、迁移或运行中的新系统。

## 优先级与验收

以下全部为 **DESIGN_DECISION**；允许已具证据的模块先开发，不等待全部52模板。

|优先级/增量|实现范围|进入条件|验收与测试|
|---|---|---|---|
|P0 / M0 契约及工程基础|独立Go服务、MySQL迁移、Vue应用、Compose本地环境、配置与秘密隔离；权限默认拒绝，操作审计；版本化规则接口|采纳10的自主设计并标记未决规则；本地种子数据完全自有|Compose启动与迁移可重复；Go服务健康检查；未认证/无权限访问测试；不接目标站API|
|P1 / M1 商品闭环|商品列表、筛选、详情、新增编辑、启用、属性/媒体；前台目录展示|04的真实字段与历史前台视觉证据充分；编码唯一性/SKU按自主约定|Go字段校验/更新冲突测试；Playwright新增自有商品→前台可见→停用策略；富文本内容处理|

|P3 / M5 扩展业务|真实供应商、面单/旺店通、售后、精细权限和更多模板|相应授权/正式契约和沙箱；52矩阵按优先级继续调查|角色×操作权限测试；供应商超时/重复回调；敏感信息日志检查；按实际需求补UI|

**DESIGN_DECISION**：服务按catalog、voucher、redemption/order、inventory、shipping、identity边界组织；net/http路由调用应用服务，事务集中在兑换/审核等用例，不分散到HTTP处理器。Vue表单适配自有API，旧URL仅作调查参考；规则策略、物流/通知适配器允许替换。

**DESIGN_DECISION**：测试重点是事务不变量和真实用户闭环，不为静态标签逐项镜像测试。MySQL集成测试验证唯一键/锁/回滚；Go testing验证权益和状态规则；Playwright只操作本地种子数据。原站写测试继续独立受授权边界约束。

## 明确阻塞与决策边界

**LIVE_OBSERVED**：3个页面读权限被拒绝，无需继续尝试绕过。**INFERRED / UNKNOWN**：原站前台选品/兑换结果和查询结果仍缺合法专用测试数据；有账号不等于允许使用实际卡券或客户手机号。**WRITE_TEST_REQUIRED**：没有业务写入授权、专用数据及恢复方案，不能验证真实核销/库存/物流联动。

**DESIGN_DECISION**：若目标是独立产品，可按上述可替换规则实施；若目标是与原站业务完全一致，M3发布前必须补齐W01–W06证据。未明确规则不会阻止公开页面和商品管理的实施，但不能承诺交易完全兼容。
