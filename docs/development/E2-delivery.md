# E2 人工发货、到店与基础物流交付

本轮实现 E2 的 MANUAL/MOCK 业务闭环，复用现有 37 表，不新增迁移。代码包括 `app/order` 发货、到店与轨迹事务、`app/shipping` 承运商目录、`infra/integrations/mock` 本地适配器、HTTP 接口及 Vue 页面。真实供应商面单、验签回调、短信和售后作业仍属 G2。

## 已实现行为

- 承运商创建、分页查询、读取与完整版本更新：`carrier.read/write` 分权；幂等摘要、目录和审计同事务。只保存供应商映射与密钥引用名，不保存明文密钥。停用承运商不能用于新发货。
- 人工全单发货：`order.ship`、版本、上海预约日、待发配送状态及开放售后检查；按商品固定顺序锁定余额和 ACTIVE 预占。实存与预占同时扣减，预占转 CONSUMED，流水关联新运单；唯一主运单、订单 SHIPPED、审计、Outbox 和幂等引用一次提交。承运商与单号重复返回 409，整个事务回滚。日额度不释放。
- 人工完成：`order.complete`、非空原因、版本及已发配送状态校验，只改变订单完成状态并审计，不生成签收事件或重复扣库存。
- 到店：`order.pickup`，现场原卡密真实 Argon2 校验，锁内复查凭证版本。只能使用已激活、封存、有效且未消费的卡；选品符合冻结权益且当前可用库存足够。直接创建 COMPLETED/PICKUP 订单、消费卡券并扣实存，写唯一账本、完成 Outbox、审计和幂等记录。无预约、预占、运单及配送地址；地址为绑定订单号的加密空对象，手机索引为随机值。重放不再次消费。
- 轨迹：顾客 ORDER READ/WRITE 只能查本单；其他订单返回 404，后台要求 `order.read`。事件标识去重，同标识不同正文拒绝；旧事件只保留事实，不倒退当前状态。可信原发 DELIVERED 只使 SHIPPED 变 COMPLETED 一次。后台人工完成不等同物流签收。
- MOCK worker：仅显式配置 `provider=MOCK` 的运单在发货后三十秒生成“MOCK 模拟运输”，六十秒生成“MOCK 模拟签收”；多 worker 重复发布按固定事件标识去重。MANUAL 不生成模拟轨迹，真实供应商目录尚未触发外部调用。

后台入口为 `/admin/carriers`、`/admin/orders/:id/ship`、`/admin/pickups`；订单详情提供人工完成及运单轨迹。顾客从订单结果进入 `/orders/tracking`。页面使用实际 API、错误态、游标分页及固定幂等键重试；卡密不持久化到浏览器存储。

## 实际验证

- `GOCACHE=/private/tmp/jst-go-cache make test`：race 单元、OpenAPI 校验/类型生成、37 表一致性、Go 构建及 Vue 类型/生产构建通过。
- `cd backend && GOCACHE=/private/tmp/jst-go-cache go vet ./...`：通过；gofmt 与 `git diff --check` 通过。
- 新建空根库 `jst_e2_final`，`go test -race -v ./tests/integration/... -count=1`：全部通过，91.624 秒。连接 EOF 是 D2 主动断开提交前连接的故障用例预期输出，断言仍通过。
- `TestMockFulfillment`：真实登录/挑战/复核、带主图商品与批准入库、卡型和批次生成、受控内存下载/封存、未激活拒绝写及激活、鉴真/选品/预约、幂等兑换、提前发货拒绝、预约日发货、订单号与手机查询 READ、MOCK 运输/签收、重复签收无重复完成事件、原卡不能重兑及第二卡仍可用。全局库存账、活动预占、核销和主运单唯一约束核对通过。
- `TestShippingTransactions`：100 个不同键同单发货只有一个成功；同键重放、跨单单号冲突整单回滚；两件商品逐项、审计和提交前故障回滚；人工完成无伪造轨迹、事件乱序/内容冲突/完成后不倒退；到店错密、错误权益、可用库存耗尽时不动其他订单预占、逐项回滚、十路并发只有一次消费及 HTTP 重放；权限、CSRF、版本、停用承运商和筛选参数检查；取消与发货争用同版本只有一个成功。

`TEST_DB_DSN=隔离测试库 make e2e` 现在执行 `TestMockFulfillment` 协议和业务服务主链。它不是 Playwright 浏览器测试。各业务用例自己创建并清理子库；完整集成测试中的迁移用例会篡改根库 checksum，下一次全量运行须使用新的空根库。
