# G2 售后与可靠异步集成

2026-10-15 实施。顾客本单 WRITE 申请、后台案件读取/决策、原单项补发和签收关闭接通真实 API。案件独立于订单状态；一个活动案件、一个补发运单，扣可用实存，不侵占其他订单预占，不恢复原卡权益。库存、运单、版本、流水、审计与事件原子提交。

自动面单使用配置的默认启用承运商。仅 MOCK 适配器默认可用；未知或未配置 LIVE 返回 503。面单绑定订单版本，READY 后还需人工按相同承运商和单号确认发货；待执行、运行及 UNKNOWN 阻止绕过。核对操作要求近期密码复核、版本和供应商工单引用，审计仅存证据摘要；已发订单不能声明作废。

Outbox 使用 SKIP LOCKED、60 秒租约、版本栅栏和稳定事件键；外部调用在事务外且限时十秒。确定失败有界退避，发送或创建结果未知进入 UNKNOWN，禁止盲重发；恢复先 Lookup 或使用供应商明确支持的同键幂等能力。关闭通知记录 SUPPRESSED；MOCK 不发外网。文件销毁事件仍由凭证服务维护，避免竞争消费者。

回调使用独立 provider 密钥、HMAC SHA256(timestamp + '.' + rawBody)、五分钟时间窗及 256 KiB 上限；按运单与供应商事件键持久去重。固定事件文案替代自由描述，避免详细地址泄漏。可选 `TRACKING_WEBHOOK_KEYS_FILE` 为供应商名到至少 32 字节 Base64 密钥的 JSON；仅部署挂载，配置 API 不返回。六小时去重拉取与三十天人工异常检查已接入 worker，未配置的适配器不伪造供应商轨迹，其专项回归继续随 H1。

验证：`TestAfterSales` race 通过，涵盖授权隔离、并发补发、逐项故障回滚和补发签收；`TestAsyncIntegrations` 通过 UNKNOWN 核对、丢回执查单恢复、旧 worker 拒绝提交及签名回调。与既有 `TestMockFulfillment`、`TestShippingTransactions` 联合 MySQL race 回归 63.325 秒通过。后续安全保守分类与调度补充待全量回归验证。
