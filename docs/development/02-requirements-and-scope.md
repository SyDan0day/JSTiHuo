# 02 需求与范围

全部实施选择为DESIGN_DECISION；原站来源引用[基线E01–E12](01-research-baseline.md)。交付独立系统，前后端真实联动，不使用demo站API、数据、Logo或卡密作为生产依赖。已观察行为保留业务语义，未知分支按18的默认规则实施，不等待原站写权限。

## 首次完整发布与明确延期

A–H完成后为v1完整自有闭环。先交付A→B→C→D作为MVP，随后E/F/G/H。所有安全、幂等、库存约束从首个业务工作包起实现，不延至最后。

外部供应商首发支持MANUAL/MOCK可运行；真实快递鸟/快递100/短信/微信适配插件默认禁用，具备正式凭据及供应商合同测试后启用。默认关闭通知，不能把外部操作成功假造为本地Toast。

不实施：支付/余额/现金退款、分次兑换、多个收货地址、原发拆包、多仓、独立SKU、金额抵扣、系统在线一键初始化、Web恢复整库、永久清空审计、卡券消费重置。原因：无已确认核心必要性且易破坏审计/一致性。功能矩阵逐项标明延期/替代，不画可点击假成功按钮。

微信菜单、图文、关注用户/黑名单、小程序码、旺店通同步、二维码任意解码为V2；仅菜单/原型证据，不阻塞提货。后台二维码工具V1可由卡号入口链接生成二维码，不含secret；通用解码不做。地区表为受版本管理的静态数据，后台区域编辑/导入延期。

## 验收口径

业务兼容范围是E01/E05–E08确认的入口、字段语义与操作类型；成功交易的未知原站规则按ADR实现，产品界面不得宣传“与原站完全一致”。测试本地种子全流程，不接受页面能点但没有持久化、库存账、核销或权限的交付。52页处理表见11与19。
